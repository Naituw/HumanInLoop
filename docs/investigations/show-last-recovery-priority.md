# Show Last 恢复后的任务优先级误判

## 核心问题

系统提示同时包含两条规则：

1. 上下文压缩后仍会看到此前的用户请求，并要求“把最后一个 User Prompt 视为当前请求，之前的请求视为旧上下文”。
2. 刚发生上下文压缩时，必须调用 AskHuman `show_last`，恢复最近一次完整的 AskHuman 问答后再继续。

本次压缩前的普通对话中残留了一条其他任务的 User Prompt；随后调用的 `show_last` 正确恢复了实际当前任务。由于第一条规则强调 User Prompt 的优先级，却没有说明 **后置返回的 `show_last` 结果应成为新的恢复基线**，Agent 仍把压缩前的旧 User Prompt 误判为当前请求。

## 实际影响

Agent 忽略了时间上更晚、内容正确的 `show_last` 恢复结果，从“分析插话支持图片和附件”错误切换到另一个历史记录需求，造成任务跑偏。`show_last` 数据本身正确，问题出在恢复后的优先级与时间顺序判定。
